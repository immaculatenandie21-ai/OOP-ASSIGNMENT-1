## How to set up and run

You need Python 3.10 or newer. Run these commands from the repository folder.

**Windows (PowerShell)**
```
python -m venv .venv
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned   # only if activation is blocked
.venv\Scripts\activate
pip install -r requirements.txt
```


**Run the tests**

```
python -m pytest
```

**Run the notebooks.** Open a notebook in Jupyter or VS Code and choose *Restart & Run All*, or run all five from the command line:
```
jupyter nbconvert --to notebook --execute --inplace project1_population.ipynb project2_microgrid.ipynb project3_fish_stock.ipynb project4_rainfall.ipynb project5_taxi.ipynb
```
Notebooks must be run from the repository root so that `from src... import ...` works. All randomness uses `np.random.default_rng(seed)`, so results are reproducible. Project 2 writes `data/demand_30days.csv` when it runs.

## Summary of findings

**Project 1: Population forecaster.** Exponential (CAGR) growth had the lowest RMSE on every district when trained on 2015-2021 and tested on 2022-2024. The Fibonacci-ratio model failed badly because it assumes about 60% growth a year. Wakiso is growing fastest (about 6.5% a year). The five districts need about 4,425 additional classrooms by 2029, assuming 2024 classrooms exactly met the 2024 need. Bootstrap 95% prediction intervals reflect noise only, not model uncertainty.

**Project 2: Micro-grid.** The system has determinant -5 and condition number 5.8, so each day has one well-conditioned solution, but feasibility needs D2/D1 between 0.5 and 1.33. Five of 30 synthetic days were infeasible (negative solar); non-negative least squares left less unmet energy than clipping (2.25 vs 5.03 kWh in total). The vectorised solve was about 25 times faster than the loop. Battery supplies most energy and 97% of the cost.

**Project 3: Fish stock.** All four harvest rates keep the stock alive, but revenue peaks at h = 0.20 (the MSY harvest rate, rK/4 = 1,000 t/week at equilibrium); h = 0.30 is overfishing. Revenue CV is about 0.10-0.11 in every scenario, so price risk is "Low" throughout; VaR and stock status separate the scenarios better than CV. An 8-week closed season reduces revenue unless fishing is beyond MSY.

**Project 4: Rainfall and crops.** Gulu has a clean maize window (April to July). Cosine similarity rates all regions as similar (0.75-0.89) while Pearson correlation is near zero, so cosine hides differences in timing. Mbarara is bimodal; Gulu's classification depends on the peak threshold; Kampala comes out unimodal, which disagrees with the usual climate description and reflects the illustrative data.

**Project 5: Taxi planner.** The Ntinda fare (UGX 2,000) is below the UGX 2,200 equilibrium, giving a shortage. Tuning chose alpha = 1.0, so exponential smoothing reduced to a last-value forecast. One vehicle per route covers the day-11 forecast. On simulated weekly data, seasonal naive clearly beats the moving average.

## Data notes

- Data marked illustrative in the brief is synthetic. **Mbarara and Jinja populations in Project 1 are invented by me**, not UBOS figures.
- Project 2 demand is generated by a seeded random generator.
- Project 4's year-to-year variability extension uses **synthetic** rainfall, not real NASA POWER or UNMA data.
- Project 4 crop thresholds come from: FAO Land & Water crop information pages for maize and beans (www.fao.org/land-water/databases-and-software/crop-information); the coffee range is anchored on the International Journal of Agronomy (2024) study "Biophysical Constraints to Robusta Coffee Productivity in Low, Moderate, and High Rainfall Areas".
